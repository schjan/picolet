# Issue tracker: GitHub

Issues and specs live in `schjan/picolet` on GitHub. Use the `gh` CLI for all tracker operations; pass `--repo schjan/picolet` when the checkout is ambiguous.

## Operations

- Read: `gh issue view <number> --json number,title,body,comments,labels,state,author,createdAt,updatedAt,url`.
- List: `gh issue list --state open --json number,title,body,labels,comments` with the relevant label filters.
- Create: `gh issue create --title "..." --body-file <file>`.
- Comment: `gh issue comment <number> --body-file <file>`.
- Label: `gh issue edit <number> --add-label "..." --remove-label "..."` as needed, preserving unrelated labels.
- Close: post the explanation first, then `gh issue close <number> --reason completed` or `--reason "not planned"`, according to the outcome.

Write multiline bodies to a temporary file and use `--body-file` so newlines and literal shell characters survive unchanged. Every issue or comment posted during triage starts with:

```markdown
> *This was generated by AI during triage.*
```

When a skill says to publish a ticket, create a GitHub issue. When it says to fetch a ticket, read the body, labels and full discussion. Consult `triage-labels.md` for role mappings.

## Pull requests as a triage surface

**PRs as a request surface: no.**

GitHub shares numbers between issues and PRs. Resolve explicitly named items to their actual type. For a range described as issues, distinguish the PRs and use them as implementation context. An explicitly requested PR can still be reviewed with `gh pr view <number> --comments` and `gh pr diff <number>`.

## Wayfinding operations

- Map: an issue labelled `wayfinder:map`, holding Notes, Decisions-so-far and Fog.
- Child ticket: use GitHub sub-issues through `gh api`; if unavailable, use a task list in the map and `Part of #<map>` in each child. Label children `wayfinder:research`, `wayfinder:prototype`, `wayfinder:grilling` or `wayfinder:task` as appropriate.
- Blocking: prefer native issue dependencies. Obtain the blocker's database ID with `gh api repos/schjan/picolet/issues/<number> --jq .id`; add it with `gh api --method POST repos/schjan/picolet/issues/<child>/dependencies/blocked_by -F issue_id=<database-id>`. If unavailable, record `Blocked by: #<number>` in the child body. Distinguish required blockers from recommended sequencing.
- Frontier: consider open children with no open blockers and no assignee, in map order.
- Claim: `gh issue edit <number> --add-assignee @me` when beginning implementation.
- Resolve: post the result, close the ticket, and add a decision pointer to the map.
