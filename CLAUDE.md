# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Picolet is a single-binary GitOps agent for managing Podman Quadlet files on Raspberry Pi fleets. Think Flux/ArgoCD, but for hosts running Podman instead of Kubernetes.

Module path: `github.com/schjan/picolet`

## Build & Test

Requires [Task](https://taskfile.dev/) runner. All commands use shared build tags defined in `Taskfile.yml`.

```bash
task build          # native binary
task build-arm64    # cross-compile for RPi (linux/arm64)
task test           # all tests with -race -count=1
task lint           # golangci-lint (v2 config in .golangci.yml)
task lint:fix       # golangci-lint with --fix
task fmt            # run all formatters (gofumpt + gci) via golangci-lint fmt
task vulncheck      # govulncheck with the build tags; fails on any finding not in .github/govulncheck-exclusions.txt
```

`go tool sops` runs the pinned SOPS CLI (Go `tool` directive in `go.mod`). `task sops:corpus` regenerates the committed SOPS fixture corpus (`testdata/sops/corpus`, encrypted to the TEST-ONLY identities in `testdata/sops/identities`); packages other than `pkg/sops` can't import getsops, so they test against that corpus and never encrypt.

`task vulncheck` runs `scripts/govulncheck.sh` (needs `jq`; govulncheck is pinned in the script, not as a `go.mod` tool, because its dependencies would bump the binary's `golang.org/x/*` modules). Locally it also reports standard-library findings fixed in newer Go patch releases; CI uses the latest patch and also runs it weekly (`schedule:` in `.github/workflows/ci.yml`; the other jobs skip scheduled runs).

**Regenerate mocks** (after changing interfaces in `pkg/applier`, `pkg/agent` or `pkg/machine`): `go tool mockery`

**Without Task**: all `go build`/`go test` commands require the build tags from `Taskfile.yml` (podman/v5 otherwise pulls in C libraries):

```bash
TAGS="remote,containers_image_openpgp,exclude_graphdriver_btrfs,btrfs_noversion,exclude_graphdriver_devicemapper"
go test -tags "$TAGS" ./pkg/reconciler -run TestName -race -count=1   # single test
go test -tags "$TAGS" ./... -update                                    # update golden files (goldie)
```

## Code Style & Linting

- **Formatters**: `gofumpt` + `gci` (import grouping: stdlib / external / localmodule) — run `task fmt` to apply automatically, never reorder imports by hand
- **Aggressive linters**: `cyclop`, `funlen`, `nestif`, `gosec`, `ireturn`, `dupl`, `containedctx`, `contextcheck` — use `//nolint:lintername` with an explanation comment when suppression is justified
- All tests must use `t.Parallel()` (enforced by `tparallel` linter), except a test that calls `t.Setenv` (Go panics on both; say so in a comment, as `pkg/sops/rules_env_test.go` does)
- `depguard` has exactly one rule: only `pkg/sops` may import `github.com/getsops/sops`

## Architecture

### Reconciliation Pipeline

The agent runs a timer-based loop (`pkg/agent`). Each tick:

1. **Health enforce** — restart inactive managed units (5min cooldown per unit)
2. **Git poll** — fetch + hard reset to remote HEAD, compare SHA
3. **Failure gate** — skip if same SHA failed 3+ times (expires after 1h; Agent startup clears it and records a `failed_sha_gate_cleared` dashboard event, since credential fixes arrive with a restart but no new SHA)
4. **Config load** — `fleet.yml`, `assignments.yml`, `hosts/<name>/host.yml` from repo FS
5. **Resolve** — merge assignments (base → role → features), render templates
6. **Diff** — compare desired files against `state.ManagedFiles` by SHA-256 content hash
7. **Validate** — quadlet files via `quadlet.Convert*()`, K8s manifests via strict unmarshal, systemd units structurally
8. **Self-restart guard** — `CheckSelfConfig` (`pkg/agent/selfconfig.go`, also run by `apply --config`) refuses a changeset that would leave the Agent a config it could not start with (see Self-Restart Guard below); the reconciliation fails and nothing is written
9. **Snapshot** — save current disk state for rollback
10. **Apply** — writes ordered by the category table's `ApplyRank` (network → volume → image → build → secret → systemd → manifest → file → pod → container → kube), then `DaemonReload`, then triggered builds (see Category Table; a failed build fails the apply → rollback), then restart changed units (alphabetical; start order comes from the Quadlet-generated dependencies; members of a restarting pod are left to the pod's `Wants=`; the Agent's own unit, also when its config secret changed, is restarted in a detached goroutine that runs while the Agent finishes the reconcile and saves the state before systemd's SIGTERM lands; a failed save leaves the old hashes, so the next start rewrites and restarts again), then rebuilt images' consumers
11. **State save** — atomic JSON write (tmp + rename) with new SHA + managed file hashes

### Self-Restart Guard

`CheckSelfConfig` (`pkg/agent/selfconfig.go`) runs before every apply of the Agent and of `apply --config`. Its policy freezes the Agent unit's mount lines through the Fleet, so the running container shows every credential as the next start will:

- **One Agent unit** — on every changeset: a resolved file other than the Agent's quadlet that is also the Agent's service (another quadlet with its `ServiceName=`, a raw unit of its name, which systemd ranks above Quadlet's generator dir, or an `[Install] Alias=` naming it) is refused (`checkOneAgentService`), since the guard reads only the Agent's quadlet. With no resolved quadlet generating the Agent's service, a changeset that updates the container quadlet the state records as generating it (now another `ServiceName=`), or deletes it while the Agent bundle stays assigned (`ResolvedHost.Services`: a rename), is refused (`checkAgentServiceKept`); otherwise it decommissions the Agent unit and is not checked.
- **Next unit** — `agentUnits`: the unit on disk is the file the state records as the Agent's service (`Change.OldServiceName`), else the file at the quadlet's path when the state does not record it (`runningUnit`); the next unit is the Fleet's render when the changeset writes the Agent's quadlet, else the unit on disk (which may hold the Host-side edit the procedure below makes before the commit), and lost sources and the config check read it.
- **Frozen lines** — a changeset that writes the Agent's quadlet may not change its frozen lines from the unit on disk (`checkFrozenLines`/`frozenChanges`: each key's values, trimmed, in order, as written; nothing semantic): the `[Container]` keys in `frozenKeys` (mounts, masks, root fs, working dir, `AddDevice`, `Annotation`, user/groups/ID maps, capabilities, seccomp, labels, `Exec`/`Entrypoint`/`EnvironmentFile`/`EnvironmentHost`, `PodmanArgs`/`GlobalArgs`/`ContainersConfModule`; the README lists them, pinned by `TestReadmeListsFrozenKeys`), the `PICOLET_CONFIG` its `Environment=` lines set (`configPath`), and every `[Service]` key but `changeableServiceKeys`. `Image=` (self-update) and every other key stay changeable. The running unit is `agentUnits.running` (so moving `ServiceName=` to another file is compared too). The refusal names the file on disk and the Host-side procedure: edit it to the new lines, `daemon-reload` and restart the Agent, then commit the same lines (until then the Agent sees no diff for the unit and leaves the hand edit alone). Without a unit on disk the lines are not compared and credentials are read as spelled.
- **Lost sources** — on every changeset: removing a Fleet-managed secret (`Secret=` or `PodmanArgs=` `--secret`, any type: `unitSecrets` in `pkg/agent/unitmounts.go`) or `.volume` unit (`Volume=`/`Mount=`) the Agent's next unit uses is refused (`checkLostSources`). With a unit on disk, whose config mount the frozen lines keep, this also covers losing a Fleet-managed config.
- **Config check** — the Agent's config is the Fleet-resolved secret the next unit mounts where the Agent reads its config (`agentConfigFile`: `configPath`, the `PICOLET_CONFIG` of its `Environment=` lines, else `/etc/picolet/config.yml`; `Secret=` read with `LookupAllArgs` as Quadlet does or `PodmanArgs=` `--secret`, each value parsed by `resolver.ParseSecretMount` as Podman's `--secret` does; the last one there wins). A config mounted otherwise (Host path, volume, data file) is not Fleet-rendered and not checked. A changeset that writes that secret or the Agent's unit must pass `agentcfg.CheckRenderedConfig` (strict loader, credential overlap, startup file checks) with every credential path absolute (`absolutePath`; `agentcfg.Load` itself still accepts relative paths for hand-managed configs). With a unit on disk each file credential is read as spelled in the running container, failing closed where a fresh start may show it otherwise (`sameView`, `freshMount`): a `--volumes-from`, a tmpfs, anonymous volume (any spelling, `VolatileTmp=` included: `unitMounts`) or image mount at the deepest mount holding it or at a target the guard cannot place (relative or with a specifier: `mayHold`), a mount from a Fleet-managed secret or `.volume` unit the changeset writes (the running container shows the old content), or no mount at all when `Image=` changes.
- **Self-restart** — an apply that writes the Agent's config secret (`agentConfigFile` of the next unit) restarts the Agent's unit (`selfConfigRestart` → `applier.WithSelfConfig`, deferred like the self-update of a changed `picolet*.container`; not in dry-run), since Podman copies a secret into a container only at creation.
- **Limits** (README) — it assumes the running container was started from the unit on disk; a config path set by `Exec=` `--config`, the image or the Host's environment, and changeable lines that still affect the next start (`Image=`'s `ENV`/`CMD`/`USER`, other `Environment=` variables the Agent reads) are not checked; without a unit on disk nothing is compared, so the next unit may mount other paths or another (or no) config secret; the content of files frozen lines name (`EnvironmentFile=`, `ContainersConfModule=`) and an image rebuilt or re-pulled under an unchanged `Image=` are not checked; `apply --config` reads credential paths as the CLI process sees them (correct only inside the Agent container) and restarts nothing for a config change (`applyWithRollback` passes no `WithSelfConfig`; a changed `picolet*.container` still takes the deferred self-update; the Agent sees no diff afterwards, so a config it wrote needs a manual restart); a commit that rewrites only a credential secret's or `.volume`'s content is not checked, nor a credential bind-mounted from a data file the Agent delivers itself (the guard reads its old content); the self restart runs before the state save, so while the state cannot be saved every start rewrites the config and restarts again.

### Category Table

`pkg/config/categories.go` holds the one category table (destination, validator `Check`, `ApplyRank`, `ConvertOrder`, `PreConvert`, health class, restart policy, resource-name prefill, unit naming) plus the extension map; every consumer derives from it. Rows with `CheckUnsupported` (`.artifact`) are known to Podman but rejected by the validator; the row is already filled in from Podman's `ConvertArtifact` (a oneshot pull service that sets its resource name, like `.image`: `PreConvert`, `HealthReportOnly`, `RestartChanged`), so enabling it means setting `CheckQuadlet` and wiring its converter in `quadletConverters` (`pkg/validator/quadlet.go`), after which `paths:` entries and Service Bundles select it by extension (`config.CategoryForPath`: a first segment `manifests/`/`files/`/`secrets/` wins, otherwise the extension map; a bundle is expanded like a `paths:` directory, bundle-relative); `Subdir` exists only on the manifest/file/secret rows (the first segment that selects them). `assignments.yml` groups take only `paths:`, `secrets:` and `services:` (`pkg/config/assignments.go`), so no category needs a schema field. `ConvertOrder` must equal `quadlet.SupportedExtensions` — a test fails on a Podman upgrade that adds or reorders extensions. Containers and pods are both `PreConvert`: the pre-pass converts containers first, filling each pod's `ContainersToStart`, so the pod's recorded dependencies list its members. `.image` is `PreConvert` (its resource name comes from conversion) and `.build` is `Prefill` (its `ImageTag`), so `Image=x.image`/`Image=x.build` resolve. `.build`/`.image` are `HealthReportOnly`: the health loop reports a unit that failed on its own under the external-activation skip reason and never restarts it, but retries a failed apply-time restart (a `PendingUnits` record) when the row's `Restart` is `RestartChanged` (`.image`) — failed restarts recorded in `PendingUnits` always need a health-loop retry path (`health.restartableByHealth`). `.build` is `RestartRebuild` (`pkg/applier/build.go`): when the unit or a file it builds from (`File=`, build context dir) changes, apply *starts* the build service (a restart would propagate through `Requires=` and stop the consumers before the build succeeds); a failed build fails the apply and puts every tag the apply's builds write back on its previous image (`PodmanClient.ImageID`/`ImageTag`/`ImageUntag`). Then running consumers (units that `Requires=` the build, from `applier.WithDependencies`) are restarted with job mode `ignore-dependencies`, so the build is not run again; consumers not running, members of a restarting pod and timer-run one-shots take the ordinary path or are skipped. A `.build` never lands in `PendingUnits`, and the health loop never restarts it.

Validation takes a `validator.Target{Rootless, HostDataDir}`; callers fill `HostDataDir` from `resolver.ResolvedHost.HostDataDir`, never recompute it. With it, `pkg/validator/build.go` fails a `.build` whose Containerfile (every path `podman build` would try for `File=`; without `File=`, the context's `Containerfile`/`Dockerfile` when the context holds delivered files), named build context (`buildunit.Paths.Context` when `NamedContext`) or `[Service] WorkingDirectory=` lies in a delivered data directory (`<HostDataDir>/files|manifests`) but is not delivered; a path outside those dirs, or one it cannot resolve from the unit (URLs, stdin `-`, specifiers, the service's default directory), may exist on the Host and passes. An empty `HostDataDir` (validator unit tests, tests on hand-filtered file sets) skips that check.

`validator.ValidateAll` (`picolet validate`) takes the Fleet FS with the resolver and config, and after resolving every Host runs Fleet-wide passes. The Agent-bundle pass (`pkg/validator/agentbundle.go`, all schemes) renders each Host's assigned Agent bundle (`config.AssignedAgentService`; unassigned Hosts are skipped) as bootstrap does, strictly and keyless with placeholder file secrets, so a provider template-function call or direct provider `secrets:` ref the bundle would need at bootstrap fails in CI, as does a `Secret=` mounted at `/etc/picolet/config.yml` that the bundle does not resolve (bundle-only, as bootstrap reads it: a config secret delivered by an assignments `secrets:` entry outside the bundle fails too); a YAML value such as `onepassword.git_token_ref: op://…` passes.

`ValidateAll` also runs Fleet-wide SOPS passes (`pkg/validator/sopsfiles.go`) over every `*.sops.*` file, referenced or not: plaintext, oversized and `.sops.yaml` rule-drifted files fail (an invalid rule is reported once per reason and hides no other rule's drift); `resolve` and the Agent run neither.

The audience pass (`pkg/validator/audience.go`) fails every age Recipient of a file that is neither an Operator's (`operators.yml`, loaded only here by `config.LoadOperators`, strict; a Recipient of an Operator and a Host fails) nor a Host's that reached the file: each host resolve records the SOPS files its refs reached in `ResolvedHost.SopsFiles` (per resolve, on the `forResolve` copy, never shared Resolver state); an unreferenced file allows Operators only, and the pass is skipped (logged) when any Host failed to resolve. A published TEST-ONLY recipient (`sops.IsPublishedTestRecipient`) declared by a Host or Operator is warned about unless `validator.AllowTestRecipients()` is passed (the example and test Fleets).

`pkg/buildunit` is the one model of which local paths a `.build`'s `podman build` reads (context directory, Containerfile candidates), in Podman's two stages with their two URL notions (Quadlet's `quadlet.URL` for `ConvertBuild`, `podman build`'s prefix check plus stdin `-` for what it reads from elsewhere); the validator's delivery check and the applier's rebuild trigger both use it, never their own path rules (the validator itself only reads `[Service] WorkingDirectory=`, which systemd must chdir into). A `.build` names data files by host path while `Change.DestPath` is where the agent writes: callers pass the resolved `DataDir`/`HostDataDir` to `applyWithRollback`, which sets `applier.WithHostDataDir`, so a containerized agent's rebuild trigger compares like with like.

### Orphan Detection & Ownership Markers

Quadlet files are written to `/etc/containers/systemd/picolet/` (picolet-owned subdir). Systemd files get `# Managed by picolet` prepended (`config.PicoletMarker`). Secrets are labeled `managed-by=picolet`. At startup, `pkg/orphan` scans for and removes Orphans (Managed Files/secrets no longer in the Fleet); it removes files only and stops no services (stopping orphaned Quadlet services is #185). A symlinked owned directory is left untouched and reported as an error, which ends that scan run. The validator rejects the agent's own container (`config.DefaultSelfUnits`) declaring `Pod=`, since restarting or stopping the pod would stop the agent.

### Interface Ownership

The three system-boundary interfaces of the Agent are **defined and implemented in `pkg/applier`**:

- `SystemdManager` — D-Bus systemd control (`DBusSystemdManager`)
- `PodmanClient` — Podman socket API (`SocketPodmanClient`)
- `FileWriter` — atomic file writes (`AtomicFileWriter`)

Other packages (`agent`, `health`, `rollback`) consume these interfaces. Mocks are generated by `mockery` in `mocks/applier/`.

Note: `SocketPodmanClient` stores a `connCtx context.Context` because the Podman binding library embeds the socket connection into the context — this is intentional (`//nolint:containedctx`).

`bootstrap machine` has its own boundary: `machine.HostOps` (`pkg/machine`, implemented by `OSHostOps`, mock in `mocks/machine/`) — the Machine's users, sessions, units and paths, a read side (checks) and a write side (applies, root). `machine.New` is the planner (Fleet + Machine + options → ordered steps with stable ids, data only, writing nothing; it reads `--secrets-dir` through an `fs.FS` that must confine symlinks — an `os.Root` in production — into a `StepDir` per subdirectory and a `StepCredential` per file, `Step.Content` never printed; a `--secrets-dir` inside the checkout is refused, since setup makes the checkout world-readable); `machine.Evaluate` derives each step's check from its kind and annotates it would do / already done / unknown (`ErrUnprivileged`); `machine.Run` checks each step the same way and applies it through the write side when not done — a failing step stops its Host only, a credential file's check picks its fix (`credentialFix`: write the content, which marks its Host "Agent restart required", or set owner/mode in place via `SetOwnerMode`), and the per-Host bootstrap phase runs `picolet bootstrap` in a container of the Host's own Podman (`RunAsUser` via `runuser`, `RunAsRoot` for the rootful Host) with the Agent quadlet's bind mounts (`agentDirs`' `mount`), so the `state.json` it seeds is keyed by container-internal paths, never `$HOME/...`; the container gets `--skip-health-wait`, so the inner bootstrap never times out on an old Agent; then it restarts an Agent marked "restart required" and waits for its health at the address `bootstrap.ResolveAgent` reads from the Fleet-rendered Agent config, and the summary lists every Host (user, port, health, restart). Writes into a Host user's home go through `os.Root` (`EnsureDir`/`WriteFile`/`SetOwnerMode` take a base and a path below it; `EnsureDir` and `SetOwnerMode` open the final element `O_NOFOLLOW`, `WriteFile` renames over it and refuses a directory there), so a symlink the user planted never leads root out of the home. `OSHostOps`' commands (`useradd`, `loginctl`, `runuser`, `systemctl`, `podman run`) are not exercised by CI (no root); verify them on a scratch VM.

`machine.Teardown` (`bootstrap teardown --machine`) runs each Host's `bootstrap teardown` in the per-Host bootstrap's container (`agentContainerCommand`, minus the checkout mount), so it reads the container-keyed `state.json`; it names the Agent with `bootstrap.FleetAgent` (no rendering, no assignment check, unlike `ResolveAgent`), so a Host whose Agent bundle is gone still tears down; users, subuid/subgid ranges and lingering stay.

### Configuration Layers

- **Agent config** (`/etc/picolet/config.yml`) — hostname, repo URL, poll interval, optional `sops:` block (`age_identity_path`, no default). Loaded by `pkg/agentcfg`. `Config.Credentials()` is the one list of credential files (add new credential settings there). `Config.CheckStartup` runs the startup file checks (credentials readable, SOPS identities parse) and returns the parsed identities (`agentcfg.Startup`, handed to the Agent with `agent.WithStartup`); `CheckRenderedConfig` adds the strict parse and credential-overlap check, reads each credential at the path its `agentcfg.Locate` gives, and is what the self-restart guard (`CheckSelfConfig`) runs on a Fleet-rendered config of the Agent's own.
- **Fleet config** (in git repo) — `fleet.yml` (images, ports), `assignments.yml` (file mappings per role/feature), `hosts/<name>/host.yml` (per-host settings incl. `machine:`/`user:`/`listen_port:`/`age_recipients:`), and the optional `operators.yml` (Operators' age Recipients; `config.LoadOperators`, read only by `validate`). Loaded by `pkg/config`. Production code opens the repo with `config.OpenRepo` (an `os.Root`-backed FS), never `os.DirFS`: `DirFS` follows symlinks out of the tree, which would let a Fleet deploy any host file (the agent runs as root). Host secrets go through `resolver.DirSecretReader`. Tests may use `fstest.MapFS`/`os.DirFS`. Loading is strict; only the Agent's reconciliation passes `config.LenientHosts()` (via `ResolveParams.LenientHosts`), so an unknown `host.yml` key or a malformed `age_recipients:` only warns there (older Agents must keep loading a Fleet that adopts a new key; one bad entry must not stop every Agent) and fails everywhere else. Every Host needs an Agent listen port: `listen_port:` or `fleet.yml` `ports.picolet_metrics` (user Hosts) / `ports.picolet_system_metrics` (rootful), so test fleets carry `picolet_system_metrics`.
- **Secrets** — read from local filesystem (`cfg.SecretsDir`), from a provider (`op://`, `pass://`), or decrypted by the Agent from a `*.sops.*` file in the Fleet (`sops://`, with the identities of `sops.age_identity_path`; see the SOPS files bullet). Every resolve driven by the Agent config (the Agent, `apply --config`, `dry-run --config`) builds its params with `agent.ResolveParamsFromConfig`; `apply --config` deliberately passes no SOPS identities (spec #248), so a `sops://` ref fails it; the no-identity error is built in one place (`sops.NoIdentityError`) and names the fix the caller passes (`ResolveParams.NoSopsIdentityHint` → `resolver.Config.NoSopsIdentityHint`; empty: `sops.NoIdentityHint`, the Agent's), which is how `apply --config` says to let the Agent apply. `dry-run` without `--config` resolves keyless (`resolver.NewKeyless`) and logs an update of a file with `ResolvedFile.SopsValues` (a SOPS value reached its render, counted by `sopsGuard`, or a direct `sops://` entry) as unverified. The flag rides on `reconciler.Change` into the persisted `state.ManagedFile.SopsValues` (an unchanged file's record is refreshed by `Changeset.RefreshNoops`), and the dashboard shows no hash for such a file, as for a secret (`dashboard.rowHash`).
- **SOPS files** (`sops.IsSOPSPath`: a base name `<name>.sops.<ext>`, `.sops.` directly before the final extension; `db.sops.yaml.bak` is an ordinary file) are reachable only through a `sops://` ref: `paths:`/Service Bundle walks skip them and SOPS's `.sops.yaml`/`.sops.yml`, and an explicit `paths:` or plain `secrets:` entry naming one (or a `paths:` entry naming `.sops.yaml`/`.sops.yml`) is rejected (`pkg/resolver/paths.go`). The Agent's secret reader refuses the Agent's own credential files (`agentcfg.Config.Credentials()`) (`agentcfg.RefuseCredentials` as the `resolver.SecretGuard`, `os.SameFile` on the opened file against every credential stat'd anew on each read, every file under a `Dir` credential); `picolet bootstrap` renders twice (placeholder secrets, then `--secrets-dir`) and refuses `bootstrapCredentials` (`pkg/bootstrap/resolve.go`): the first pass's rendered Agent config's credentials (`Config.CredentialsAt`: a credential below `secrets_dir` also at its place below `--secrets-dir`) plus, always, `--secrets-dir`'s `age-identity` and the provider token names `bootstrap machine` places there (`onepassword.TokenFileName`, `protonpass.PATFileName`; covers a config that names none or that the Fleet does not render); the second pass, which is deployed, must yield the same list, and `agentcfg.Load` fails when two credential settings name the same file. SOPS readers are passed explicitly as `resolver.Config.Sops` (a `resolver.SopsReader`: `ReadAll` for `readSopsSecret`, `ReadData` for `readSopsData`'s subtrees, one reader per resolve so both share its per-file cache; `ReadData` bypasses the two-phase `RefCache` and runs in the collect pass too): `validate`, `resolve`, `dry-run` without `--config` and bootstrap build their resolver with `resolver.NewKeyless`, which builds the keyless one per Host resolve (`keylessSopsReader(fsys, host)` in `pkg/resolver/registry.go` → `sops.NewKeylessReader` with the Host's `age_recipients:`; it fails a ref when the Host declares none or when they do not reach every key group the file needs (`sops.ErrNotRecipient`), renders `<sops-secret>` for an encrypted string leaf or whole file, a typed placeholder for an encrypted int/float/bool/time leaf (`0`, `0.0`, `false`, zero time, from the ciphertext's type tag, `keylessFile.leaf`; direct `secrets:` refs keep `<sops-secret>`), so a typed field of a strictly validated file passes, and plaintext leaves as the Agent does, reads no key; it walks the file through upstream's tree decrypt with a placeholder cipher (`pkg/sops/keylesstree.go`), so the file's encryption rules decide what is encrypted, and it must never fail a per-ref read the decrypting reader accepts — `TestKeylessAcceptsWhatDecryptingAccepts` pins that over the corpus; only the recipient checks and the Fleet-wide passes are validate-only); the Agent and `dry-run --config` pass `agent.ResolveParams.SopsIdentities` (from `agentcfg.Config.LoadSopsIdentities`, the `sops.age_identity_path` file, parsed by the startup checks and so by the self-restart guard), and `loadAndResolveHost` builds one decrypting `sops.Reader` per host resolve (each file decrypted once; never package-level), whose `Scrub` every reconciliation error passes through (`agent.scrubError`) before it reaches logs, events, deployment statuses or MQTT; with none, a `sops://` ref fails the resolve (no placeholder, unlike `op://`/`pass://`), and strict mode fails every `readSopsSecret`/`readSopsData` call. Direct `sops://` `secrets:` entries (named by `Ref.SecretName` in `secretDestPath`, so collisions fail like any destination) resolve in `resolveSopsDirectRefs` through the same per-resolve reader (`directSopsReader`: keyless `KeylessReader.ReadDirect`, or the decrypting reader with `""` rejected, both `sops.ErrEmptyValue`); they are never skipped, and strict mode fails them even with the keyless reader. A Quadlet, Raw Unit or Hook definition render that calls `readSopsSecret` or `readSopsData` (also through `renderTemplate`) fails with `resolver.ErrSopsInUnitFile` in every path (the provider's `Guard`, keyed on the top-level file `withRender` sets, `pkg/resolver/sopsguard.go`), and its refs are never collected, so no reader sees them.
- **Bootstrap credentials** — `host.yml` `bootstrap:` / `fleet.yml` `bootstrap.files|roles` (`config.BootstrapFiles`, effective block in `HostConfig.Bootstrap`, most specific level wins whole; nil = no block = the Host gets the Machine's provider token, `{}` = declared, gets nothing). Read only by `pkg/machine`; providers are injected as `machine.Providers` (production wiring in `pkg/cli`), so tests never open 1Password or pass-cli.

### Template System

Files ending in `.tmpl` are rendered with Go `text/template` (`missingkey=error`). All templates share a single `template.Template` registry enabling cross-references.

Custom functions: `readFile`, `renderTemplate`, `indent`, `readSecretFile`, `readOpSecret`/`readProtonPassSecret`/`readSopsSecret`/`readSopsData` (provider registry, `pkg/resolver/registry.go`), `siblings` (other Hosts on this Host's Machine, sorted by hostname), `has` (slices.Contains for feature checks).

Template data root: `.Host` (hostname, role, features, machine, user, rootful, listen_port, age_recipients, services, systemd_units), `.Fleet` (full config + all hosts), `.Images`, `.Ports`. `.Host.SystemdUnits` is populated by a first render pass — see `prepareTemplateData` in `pkg/resolver/resolver.go`.

### Error Patterns

- Wrap with `fmt.Errorf("context: %w", err)` consistently
- Custom error types: `*resolver.HostNotFoundError` and `*applier.HookFallbackError` (check with `errors.As`); `pkg/agent`'s `scrubbedError` deliberately does not unwrap (it answers `errors.Is` only), so no caller reaches the unscrubbed text
- `errors.Join` for accumulating validation errors in `pkg/validator`
- Result structs with `Errors []error` fields for non-fatal errors (health checks, apply)
- The resolver's own template-function errors (strict mode, no reader, the SOPS unit-file guard) name their ref by `refForError` (`pkg/resolver/registry.go`: scheme and file or vault, never a `sops://` pointer or an `op://`/`pass://` item or field), an unresolved render-time ref by its function only, and a provider reader's error passes `redactRefs` (its `op://`/`pass://` refs in `refForError`'s form, longest first): a template may build the ref from a secret value, and only SOPS values are scrubbed. The SOPS readers' own errors (`pkg/sops`, `checkSopsRef`) quote the full `sops://` ref, and apart from it the pointer and its failing key: `redactRefs` keeps them for a ref the collect pass saw, and a render-time ref (a `readSopsSecret`/`readOpSecret`/… cache miss, or a `readSopsData` ref the collect pass did not read, recorded in `RefCache.dataRefs`) gets `dynamicRefError` instead: the reader's text is withheld, leaving the function, `refForError`'s form and the SOPS error class (`errors.Is` still answers), since a template may build that ref from an `op://`/`pass://` value
- A reconciliation error may embed a value decrypted from a `sops://` ref: every reconciliation error the Agent records as a dashboard event or returns from `ReconcileOnce` (and the validation errors it logs) passes through `scrubError` (`pkg/agent/sops.go`) with the one `sops.Reader` of that resolve first, as do the apply's own log lines (rollback notice, non-fatal apply errors); CLI callers scrub with the function `agent.LoadAndResolveHost` returns

### Testing Patterns

- **Unit tests**: mockery-generated mocks with `.EXPECT()` fluent API; `pkg/applier` has an in-package `memFileWriter` for self-testing
- **Integration tests**: `integration_test.go` at root uses `testdata/example-fleet/` with `goldie` golden-file snapshots
- **Agent integration**: `pkg/agent` tests build a real git repo via `go-git` (`initFleetRepo`) and drive the full loop through `newLoopHarness` (`pkg/agent/harness_test.go`: `loopConfig`, mocks recording what the Agent applies, `run`/`runUntilApplied`/`tick`)
- **SOPS fixtures**: `internal/testsops` reads the corpus (files, recipients, identities) and holds the leak assertion (`AssertNoPlaintext`); it imports `pkg/sops`, so `pkg/sops`'s internal (package `sops`) tests cannot use it

### Package Dependencies

`pkg/state`, `pkg/gitpoll`, `pkg/status`, `pkg/buildunit`, `pkg/sops` and `internal/secretref` are fully standalone. `internal/secretref` is the one `<scheme>://<scope>/<item>/<field>` reference parser and Podman secret naming behind `pkg/onepassword` (`op://`) and `pkg/protonpass` (`pass://`), whose `OpRef`/`PassRef` alias its `Ref`. `pkg/sops` is the only importer of getsops (depguard): keyless inspection (`Inspect`/`InspectFile`/`File.Lookup`, 1 MiB cap via `ReadFile`; readers decrypt the tree `Inspect` parsed), RFC 6901 pointers, the `.sops.` path rule and Podman secret naming (`ParseRef`, `Ref.SecretName`), and canonical age recipients (`ParseRecipient`: X25519 and hybrid post-quantum only), and `.sops.yaml` creation rules (`ReadCreationRules`: Fleet-root only, `Lstat` through the Fleet FS, a symlink or an FS without `fs.ReadLinkFS` fails, copied into a private temp dir that `Close` removes; `CreationRules.Check` picks the rule with upstream's `config.LoadCreationRuleForFile`, never a reimplementation: no `creation_rules` or upstream's no-match error, detected by its text and pinned by `TestNoMatchingRuleText`, passes, any other load error is `ErrInvalidCreationRule`; then it compares the rule's age Recipients with the file's group by group; the temp copy is reduced first (`ageOnlyRules`: each rule keeps `path_regex`, `age`, `key_groups` cut to `age`/`merge`, `shamir_threshold` and the encryption-rule fields, decoded with `go.yaml.in/yaml/v4` (the repo's YAML library) into upstream's field types; every non-age key, `destination_rules` and `stores` are dropped and never decoded, so a value upstream would refuse there passes; the temp copy needs a writable `TMPDIR`), so upstream's loader never builds a non-age backend (a versionless `azure_keyvault` URL would discover credentials and look its version up over the network); a rule left without age keys still matches, as one empty group). `pkg/status` is a process-local in-memory runtime store consumed by `pkg/agent`, `pkg/dashboard`, and `pkg/metrics`.

`pkg/metrics` exposes Prometheus collectors. Custom collectors that read runtime state accept a `*status.Store` at construction (`metrics.Register(store)`); no package-level mutable state. `pkg/metrics` imports `pkg/status` (one direction; no cycle). The Agent records its runtime metrics (secret-provider sync, failed-SHA gate, managed files per category) in its `status.Store`, and `metrics.Collectors(store)` is the single list of `/metrics` collectors that read it at scrape time; never add a package-level collector the Agent sets directly.

Logging is injected: `agent.WithLogger` feeds config load, resolver (`resolver.Config.Logger`), validator, applier, health, rollback, gitpoll and orphan, each of which takes its own `WithLogger` option (default `slog.Default()`); `pkg/agent`'s `TestMain` fails the package when a record reaches the global slog default, so never call `slog.Info`/`slog.Warn` etc. directly on those paths.

Everything else flows through `pkg/agent` which orchestrates the pipeline.
